- [x] **Per-tense conjugation toggle** (requested 2026-09-06): `AppSettings.disabledTenses` — a disabled tense (e.g. "présent") is excluded from *every* conjugation card shown, including ones already in learning/review, not just new introductions. Filtered directly in SQL (`tense NOT IN (...)` on both the review and new-card queries in `getDueConjugationCardsSplit`) since `tense` is a plain column, unlike vocabulary's JSON `tags` array (see below — `disabledTags` was originally weaker here, since fixed to match). UI: toggle chips in Réglages → Conjugaison, same component as the existing theme chips. Verified against a real in-memory SQLite DB (not just compiled): seeded cards across 3 tenses, disabled one, confirmed it's absent from results and that no filter returns all three. `tsc`/`jest` green (129/129).
- [x] **Keyboard grade shortcuts** (requested 2026-09-06): pressing 1/2/3/4 during review triggers Otra vez/Difícil/Bien/Fácil — `useGradeKeyboardShortcuts` hook (web-only), wired into the 4 review screens that have these buttons (vocab, conjugation, expressions, reading; listening auto-grades, no 4-button UI to hook). Only active once the buttons are actually shown, so it never intercepts a conjugation/listening answer being typed.
- [x] **Per-level (CECRL) vocabulary toggle** (requested 2026-09-10): `AppSettings.disabledLevels` — same strong semantics as `disabledTenses` (total exclusion, including cards already in progress), reusing a new shared `notInClause` helper for both. Verified against a real in-memory SQLite DB: disabling B1 removed it from new cards, and a B1 card already advanced to "learning" *before* disabling still disappeared — confirms the total-exclusion behavior, not just the weaker new-card-only filtering `disabledTags` does. Note: "B2" carries no actual words in the generated dataset (see Later), so disabling it has no visible effect yet.
- [x] **"Lexis cannot be closed" installer failure** (reported 2026-09-10): no Lexis/Electron process was actually running when checked, so the likely cause was the app still being open when the installer ran — normal installer behavior, not a bug. Found and fixed one real contributing edge case anyway: `captionsFetcher.ts`'s hidden `BrowserWindow` counts as an open window for Electron, so if the user closed the main window while a captions fetch was still in flight, full process exit could lag up to ~9s behind the visible window closing. `before-quit` now force-destroys any remaining windows immediately.
- [x] **Listening search returned no results** (reported 2026-09-11): same CORS bug class as DeepL/Open Library, just never applied to this feature — `searchYoutubeVideos`/`fetchVideoMetadata` called `fetch` directly from the renderer against two endpoints confirmed (via `curl`) to send no CORS headers, so both were silently blocked, degrading to `[]`/`null` by existing design rather than an error. Moved both to the main process via IPC (`searchIpc.ts`). Verified for real: called outside a browser context, both return genuine data (7 results for a test query, correct metadata for a direct video ID).
- [x] **"Écrire les mots" vocabulary mode** (requested 2026-09-11): a second way to review vocabulary alongside the existing flashcards — English word shown, Spanish typed and checked (`isExactMatch`, already shared with listening dictation), then the same 4 grade buttons self-grade like conjugation's typed mode. `WritingReviewScreen.tsx` + `WritingReviewContainer.tsx`, new `vocabWriting` session type in `RootTabs.tsx`, a second button on Aujourd'hui. Deliberately reuses `getDueCardsSplit`/`getMoreNewCards` byte-for-byte from the flashcards container — same due-card pool, same `disabledTags`/`disabledLevels` filters, no separate filtering logic to maintain or diverge. `tsc`/`jest` green (129/129); the tag/level filtering itself isn't re-tested here since it's the identical, already-verified function calls, not new logic.
- [x] **Theme deselection didn't actually work — confirmed BUG, now fixed** (reported 2026-09-11): user disabled every theme except "cuerpo" but kept seeing other themes' words. Root cause confirmed directly against the user's real database: `disabledTags` had only ever filtered *new* cards (original, documented design) — 62 cards already past "new" existed in their real data, 57 outside the one enabled theme, all still surfacing regardless of the toggle. Fixed to match `disabledLevels`/`disabledTenses`'s total-exclusion semantics, using SQLite's `json_each` (JSON1 extension, confirmed available under `node:sqlite`) to filter the JSON `tags` array directly in SQL on both the review and new-card queries — removes the old JS-filter/over-fetch-margin workaround entirely. Verified by reproducing the exact reported scenario in a test DB (a tag disabled after a word from it was already "learning") — confirmed absent from results.
- [x] **Favor new words over already-seen ones** (requested 2026-09-11, vocabulary and conjugation): `pickWeighted` (`utils/shuffle.ts`) — the "next card" pick in all three review containers (flashcards, écriture, conjugaison) now counts each new (never-reviewed) card 3× in the draw instead of once, without changing the actual due-card count used elsewhere (Aujourd'hui's "X cartes dues"). Verified statistically (100,000 draws): a pool of 3 review + 1 new card went from a 25% (uniform) to a ~50% chance of drawing the new card, matching the expected math for a 3× weight.
- [x] **Video audio playing in the background while adding it** (reported 2026-09-12): the hidden `BrowserWindow` used to fetch captions loads the real `youtube.com/watch` page, which autoplays — `show: false` only hides the window, it doesn't mute it. Fixed with `webContents.setAudioMuted(true)` right after window creation.
- [x] **Captions returning 0 segments on every video — confirmed BUG, now fixed** (reported 2026-09-12): three real, distinct bugs found by live-testing every stage of the pipeline, not by guessing — see `docs/AUDIT.md` Facts for the full diagnosis (GDPR consent-dialog backdrop swallowing clicks because this machine's VPN exits through Oslo/EEA, the transcript button needing the description expanded first, and — the decisive one — YouTube having renamed its transcript-panel endpoint from `get_transcript` to `get_panel` with a new "ViewModel" JSON shape that neither the URL filter (`captionsPreload.ts`) nor the body parser (`transcriptParsing.ts`) recognized. All three fixed; DOM-scraping was confirmed to remain unreliable in this hidden-window context even after every other fix (the panel's lazy-load mechanism never fires while non-visible), so the fix relies on intercepting the network response directly instead. **Verified end-to-end**: `fetchTranscriptForVideo` against the rebuilt `electron-dist` output returned 23 real Spanish segments for a real video. `tsc` (app + electron) and `jest` green, including new unit tests for the `get_panel` JSON parser.
